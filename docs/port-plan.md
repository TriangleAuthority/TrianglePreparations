# Port plan

## Where the port stands

**2026-11-14: slice 4 done.** The baselines and the legacy mod are committed ([repository.md](repository.md)); the legacy mod is described in [legacy-mod.md](legacy-mod.md) and compared with 5.x in [preparations-5.x.md](preparations-5.x.md) (read from the files, **unverified** in game where not stated). Slices 0 to 4 are **verified** in game with Ghost Mode installed: PREP-MENU, PREP-MED, PREP-COMBAT, PREP-INV, PREP-SKILL, PREP-TIME, PREP-ALCH, PREP-REFILL, PREP-OIL and PREP-TABLE (below); Ghost Mode's regression passes beside it in both trees (classic 1673/0, new 1698/0, panel 166/0 each). Next: slice 5 (PREP-REST, PREP-FIX). Open for the owner: the native-function wrapper behind the charges in recipe names (below).

## Approach

As in TriangleGhostMode and TriangleGwentImprovements: reproduce the legacy mod's behaviour in the least invasive 5.x form (wrappers first, replacements only where a wrapper cannot do it, XML through the mod's own DLC), one small slice at a time, each verified in game, in both skill trees. Legacy bugs are fixed when found and listed as deviations. The mod's DLC: `modPreparations/files/dlc/dlcpreparations/` (id `dlc_preparations`); prefix for everything the mod adds: `Prep`/`prep` (legacy already uses it for its options).

## Decisions made

- **The alchemy-table effect type** (owner, 2026-11-14): Preparations keeps legacy's effect, with its own `EEffectType` member declared after a copy of Ghost Mode's effect type names in Ghost Mode's order. The game merges mods' enum members by name at load, and this is the one form found that keeps both mods' effects working (**verified** with a probe, TriangleGhostMode `docs/development.md`). Rules: the copy is updated whenever Ghost Mode adds an effect type (Ghost Mode only appends at the end), a check compares it with Ghost Mode's list before each release, and Preparations' member stays last. The other fixes in [ghost-mode-compatibility.md](ghost-mode-compatibility.md#combining-cleanly-without-a-patch-analysis-2026-11-13) are decided too (owner, 2026-11-13).
- **Notifications from the meditation checks** (PREP-MED; owner, 2026-11-14): `CanMeditate`, `CanMeditateHere` and `CanMeditateWait` are silent, and the reason a meditation is refused shows only when the player tries to meditate. 5.x polls `CanMeditate` from the radial menu, the common menu and the input code, so legacy's notification on every call would flood the screen.
- **Skill purchase time is charged on confirm** (PREP-TIME, PREP-SKILL; owner, 2026-11-14): in a wrapper of `handleBuySkillConfirmation` in both character menus, so the classic tree's confirmation popup and the new tree's direct upgrade both charge it, and a cancelled popup does not. Legacy charges when the classic popup opens, cancelled or not (a deviation, recorded when built).
- **No replenish without meditating** (PREP-MED; owner, 2026-11-14): meditation is refused while waiting is blocked, as in legacy (`prep_error_action_disallowed`, "Meditation is blocked for now"). This closes 5.x's radial-menu shortcut that, only while waiting is blocked (quest moments, elevators, ...), restores Geralt and refills alchemy at once without time passing. **Verified** (scripted, waiting blocked by `BlockAction`).
- **Charges in recipe names, with wrappers only** (PREP-REFILL; owner, 2026-11-14: no replacement of 5.x's long `PopulateData`): a `PopulateData` wrapper marks the name keys of held singleton items (keys shared by two recipes' items are left alone), and a class-less wrapper of the native `GetLocStringByKeyExt` appends legacy's ` | charges/max |` to those keys only while `PopulateData` runs. **Verified** (the held Swallow's name built as "Swallow | 1/3 |" in the open menu's list, plain everywhere else; the list not looked at on screen).
- **5.x's auto-applied oils** (PREP-OIL; owner, 2026-11-14): each automatic application costs a jar charge, and it is refused in combat while "Disallow applying oils in combat" is on, like applying from the inventory.
- **5.x's oil re-apply when brewing a stronger oil** (PREP-OIL; owner, 2026-11-14): costs the new jar a charge, like any application.

## Decisions to make

- **The native-function wrapper** (PREP-REFILL): the charges in recipe names need a wrapper of the native `GetLocStringByKeyExt`. TriangleGhostMode's rules ask for the owner's agreement before wrapping a native function, since a loose-script version cannot carry it. Keep it, or drop the charges in names.

- **Friendly Meditation preset**: legacy asks the player to apply it in every group; the port could detect FM (its option group reads non-empty) and say so, or apply it.
