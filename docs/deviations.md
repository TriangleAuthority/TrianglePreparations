# Deviations from the legacy mod

Every place where the port behaves differently from Preparations 6.2, with the reason, who decided and when, and a question for the original author (wghost81) where their intent is unclear. Add an entry whenever the port deviates, in the same commit.

"Owner" is this project's owner; "porter's call" means not yet confirmed by the owner.

| # | Feature | Legacy | Port | Why | Decided | Question for the author |
|---|---|---|---|---|---|---|
| 1 | PREP-MENU | The defaults come from `user.settings` lines the player pastes by hand; without them most options are off | Every option has its default in script (legacy's "Defaults" preset, the same values); options never set get it when a save loads, and the reads fall back to it | No manual install step; same values as legacy's install | Porter's call (as planned in [port-plan.md](port-plan.md)), not confirmed by the owner | None |
| 2 | PREP-MED | `CanMeditate`, `CanMeditateWait` and `CanMeditateHere` show the reason as a notification on every call | The checks are silent; the reason shows once when the player tries to meditate (N, the radial menu and its key, the minimap's clock), in place of 5.x's generic message when Preparations' rules refused. The panels' Meditation tab is greyed out by 5.x without a message; a clock menu already open shows 5.x's "cannot do that now" | 5.x polls `CanMeditate` from the radial menu, the common menu and the input code, so legacy's notification would flood the screen | Owner, 2026-11-14 | None |
| 3 | PREP-MED | Its own checks also refuse meditation while a quest pauses game time and when submerged | 5.x's own `CanMeditate` checks run instead for these (5.x refuses in shallow water; with time paused it lets Geralt sit down, and its clock refuses to wait). Waiting blocked refuses meditation as in legacy | 5.x splits sitting down from waiting | Porter's call, not confirmed by the owner | None |
| 4 | PREP-SKILL, PREP-TIME | Buying a skill with the classic tree's upgrade button costs time when the confirmation popup opens, also when it is cancelled | The time is charged when the purchase happens (`handleBuySkillConfirmation`): the popup's confirm, or the new tree's direct upgrade; a cancelled popup costs nothing | Charging a cancelled purchase looks like a bug, and the new tree has no popup | Owner, 2026-11-14 | Was charging before the popup intended? |
| 5 | PREP-SKILL (new tree) | Legacy had only the classic tree and its character screen | The same rules and time costs apply in the new tree's character screen (`CR4CharacterDupeMenu`), which Ghost Mode also uses for its classic tree | 5.x has two trees and two screens; Preparations covers both | Porter's call (the project's two-tree rule), not confirmed by the owner | None |
| 6 | PREP-REFILL | A held item's recipe name shows its charges in the alchemy menu (` | 2/3 |`) | Not shown; the refill cost shows as the ingredient list | It needs a replacement of 5.x's long `PopulateData` | Owner, 2026-11-14 | None |
| 7 | PREP-REFILL | A held item hidden with `NoShow` passes the refill check (refill cost) but is then brewed as new (full recipe) | Not a refill: 5.x's own brewing handles it | Legacy's check and action disagree; 5.x's handling is consistent | Porter's call, not confirmed by the owner | Which was meant? |
